1) DISCORD COMMAND SET (MVP, MUST IMPLEMENT)
========================================================
Discord bot runs in each tenant channel and supports slash-like commands (prefix "!"):

Core commands
- !help
  - Show available commands and quick examples
- !status
  - Show current orchestrator status for this tenant:
    - enabled/disabled
    - webhook health last seen
    - queue depth
    - active runs (issue key, stage, elapsed)
- !runs [N=10]
  - List last N runs with status, issue key, PR link (if any)
- !run <ISSUE_KEY>
  - Force-run a Jira issue NOW (only if issue is in executable status “To Do” and not already running)
  - If not eligible, reply with reason and link to Jira.
- !cancel <RUN_ID>
  - Mark run as cancelled (best-effort). Must:
    - stop further agent steps
    - comment on Jira + Discord “cancelled by <user>”
  - Note: cancellation may not interrupt mid-command; it stops future steps.
- !retry <ISSUE_KEY|RUN_ID>
  - Re-run a failed run (must create a new run_id) if issue is still eligible.
- !promote <ISSUE_KEY> (optional)
  - If enabled for tenant: move issue from Backlog to To Do (human gate shortcut)
  - Disabled by default (because Jira permissions vary by client).

Diagnostics / guardrails
- !policy
  - Post a short summary of key rules (no secrets, no sleeps, state machines, testing required).
- !link <ISSUE_KEY>
  - Print Jira link + latest PR link (if exists)

Permissions
- Only allow sensitive commands (!run, !cancel, !retry, !promote) from a Discord allowlist of user IDs.
- !help, !status, !runs, !policy, !link allowed for all channel members.

2) PRINCIPLE-LEVEL ENGINEERING STANDARDS (MUST ENFORCE)
========================================================
Create a repo-level standards folder if missing:
- .codex/ENGINEERING_STANDARDS.md  (single source of truth)
- .codex/standards/ (optional per-language docs)

Agents must read .codex/ENGINEERING_STANDARDS.md BEFORE coding and treat it as hard constraints.

ENGINEERING_STANDARDS.md must include:
A) Architecture principles
- Prefer clear boundaries: domain/application/infrastructure separation where applicable.
- Use interfaces/abstractions at boundaries (ports/adapters).
- Keep side effects at the edges; core logic should be testable without external services.

B) SOLID & OOP guidance (when in OOP languages)
- Single Responsibility: small classes/functions with one job.
- Open/Closed: extend via new implementations not edit-heavy branching.
- Liskov: respect contracts for derived types.
- Interface Segregation: small interfaces.
- Dependency Inversion: depend on abstractions; inject dependencies.
- Avoid “god services”; prefer composition.

C) Concurrency & timing policy (CRITICAL)
- NEVER use time-based sleeps (Thread.sleep / setTimeout waits / arbitrary delays) as synchronization.
- Prohibited patterns:
  - Thread.sleep(...)
  - await new Promise(r => setTimeout(r, ...)) to “wait for state”
  - polling loops without bounded backoff and clear termination

- Required alternatives (choose the right one):
  1) State machines:
     - explicit states + transitions + events
     - persist state when workflow is long-running
  2) Event-driven design:
     - publish events; react to events; no waiting
  3) Condition-based waits:
     - wait for a specific condition with a timeout and meaningful error
     - example: await expect(locator).toBeVisible({ timeout: 5000 })
  4) Deterministic clocks in tests:
     - fake timers or injected clock rather than real sleep

- If a delay is genuinely required (rare):
  - must be justified in code comment
  - must be bounded and paired with a condition check
  - must be reviewed by Reviewer agent as “acceptable exception”

D) Error handling & observability
- No swallowing exceptions.
- Return typed errors or structured exceptions.
- Log with correlation IDs; never log PII/secrets.
- Prefer idempotent handlers for event processing.

E) Minimal diffs
- Do not reformat unrelated code.
- Do not upgrade dependencies unless required.

4) REACT/FRONTEND TESTING STANDARD (MUST IMPLEMENT)
========================================================
Default stack:
- Unit/Component tests: Jest + React Testing Library
- E2E (optional): Playwright
- Assertions must be condition-based (no arbitrary waits)

Rules:
- Prefer testing user-visible behavior over implementation details.
- Use role/text queries (getByRole, findByRole).
- Avoid fragile selectors.
- For async UI:
  - use findBy* / waitFor / toBeVisible with timeouts
  - NEVER use setTimeout-based waits to “let it settle”
- Mock network with MSW where appropriate.
- Each meaningful UI behavior change requires at least one test.

Example patterns to enforce:
- Good:
  - await screen.findByRole('button', { name: /submit/i })
  - await waitFor(() => expect(mockFn).toHaveBeenCalled())
- Bad:
  - await new Promise(r => setTimeout(r, 1000))
