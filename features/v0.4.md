CHANGE: Backlog vs To Do execution gating

========================================================
1) EXECUTION GATE (PRIMARY RULE)
========================================================
Principle:
- Jira “To Do” is the execution queue.
- Agents MUST ONLY execute work on issues in “To Do”.
- Jira “Backlog” is explicitly non-executable.

Tenant config additions:
- jira:
    - executable_statuses: ["To Do"]   # allow list; per tenant
    - non_executable_statuses: ["Backlog"]
    - executable_jql must include:
        status in ("To Do") AND statusCategory != Done

Queue rule (hard requirement):
- An issue is eligible for execution if:
  - status in tenant.executable_statuses
  - NOT already locked/running
  - statusCategory != Done

========================================================
2) JIRA WEBHOOK TRIGGER
========================================================
Webhook ingestion:
- Enqueue execution when:
  - issue transitions INTO an executable_status (e.g. Backlog → To Do)
- Ignore issues created directly in To Do unless explicitly enabled.

Idempotency:
- Multiple webhook events must not create duplicate runs.

========================================================
3) AGENT-CREATED ISSUES
========================================================
Agents MAY create Jira issues for:
- Bugs discovered during implementation
- Missing tests
- Follow-up improvements
- Tech debt

Rules:
- Agent-created issues MUST be created in Backlog (or default backlog status).
- Agents MUST NOT move issues into To Do.
- Agents MUST link created issues to the originating issue or PR.
- Agents SHOULD notify via Discord when follow-up issues are created.

========================================================
4) AUTOMATION VS EXECUTION AGENTS
========================================================
Execution agents (PM / Dev / Test):
- Trigger: Jira issue in executable_status (“To Do”)
- Purpose: implement code and open PRs

Automation agents (Reviewer / CI Analyst):
- Trigger: GitHub events (PR opened, PR updated, CI failure)
- Purpose: review, comment, flag issues
- MAY create Jira issues (Backlog only)

========================================================
5) DISCORD MESSAGING RULE
========================================================
Discord bot responses must reflect this model:
- If asked “why didn’t it run?”:
  - “Agents only execute issues in To Do. Backlog items are not executed.”
