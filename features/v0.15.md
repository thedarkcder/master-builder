========================================================
1) REQUIRED GITHUB ACTIONS WORKFLOWS
========================================================
Create GitHub Actions workflows in this repo (MASTER-BUILDER) AND provide templates that can be bootstrapped into target repos.

Workflows to add (minimum):
A) .github/workflows/ci.yml
- Trigger:
  - pull_request (opened, synchronize, reopened)
  - push to main (optional)
- Jobs:
  1) lint
  2) unit-tests
  3) build (if applicable)
- Must support matrix based on detected project type:
  - Java/Spring: setup-java, cache maven/gradle, run ./mvnw test or ./gradlew test
  - Node: setup-node, cache, pnpm/yarn/npm install, run lint + test
  - Python: setup-python, install deps, run ruff + pytest
  - React: same as Node; ensure test runner uses CI mode

B) .github/workflows/security.yml
- Trigger:
  - pull_request
  - schedule (weekly)
- Jobs:
  1) secret scanning / gitleaks (or equivalent)
  2) dependency vulnerability scanning (choose one feasible default):
     - GitHub code scanning (CodeQL) where possible
     - OR dependency review action on PR
  3) SAST baseline (CodeQL if enabled)
- Output:
  - annotate PR with findings
  - fail the workflow on high/critical findings by default

C) .github/workflows/dependency-review.yml (optional but recommended)
- Trigger: pull_request
- Job: GitHub Dependency Review to flag new vulnerable deps

D) .github/workflows/auto-label.yml (optional)
- Trigger: pull_request
- Auto-label based on paths (api/storage/discord/admin-ui/etc.)

========================================================
2) PR “READY” DEFINITION MUST INCLUDE CI PASS
========================================================
Update “PR Ready” logic:
- A PR is “Ready” only when:
  - CI workflow passes (lint/tests/build)
  - Security workflow passes (or has no high/critical)
  - Reviewer agent has posted review summary
- If checks are pending/failing:
  - Post a short Discord update: “PR opened, checks running/failing” (no noise)
  - Do NOT ping as “ready” until green.

Reviewer agent behavior:
- On PR open/update:
  - read GitHub check results
  - if failing:
    - summarize the failure (top 1–2 causes)
    - propose fix or create follow-up Jira issue if out of scope
  - only post “✅ PR Ready” when checks are green.
